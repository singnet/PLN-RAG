# SENF Full Implementation Map

## Scope

This document maps the practical, finite SENF and TransWeave work proposed in
the design PDF to the implementation in this repository. The mapping uses the
MVP phases as engineering boundaries rather than claiming that the Python data
structures implement the full mathematical objects used by the PDF.

The implementation deliberately excludes full Homotopy Type Theory (HoTT),
univalence, higher inductive types, and infinity-groupoids. There is no proof
assistant, univalence axiom, path induction, higher-cell representation, or
machine-checked correspondence between the bounded algorithms here and those
theories. `Entity`, `IdentityEdge`, frame alignment, and branch ancestry are
finite application records and heuristics. Terms such as identity, transport,
fibration, or weave must be read in that practical sense.

The production-safe baseline remains `canonical_pln`. SENF is selected with
`PARSER=canonical_senf_pln`; several consequential behaviors remain separately
opt-in. Configuration defaults are defined in `config.py`. Docker Compose
currently forwards only the feature-provider settings in `docker-compose.yml`,
so other SENF settings must be added to that service environment or supplied by
another deployment mechanism before they can be changed in the container.

## End-to-end path

1. `parsers/canonical_senf_pln_parser.py` subclasses the canonical parser, so
   canonical generation, symbol normalization, statement validation, and query
   fallback remain authoritative.
2. `core/senf/extractor.py` deterministically projects accepted named MeTTa
   statements and their source text into the typed records in
   `core/senf/types.py`.
3. `core/senf/feature_provider.py` may obtain advisory evidence. The evidence is
   validated by `core/senf/features.py` and attached only to exact existing
   mention spans by `core/senf/feature_binding.py`.
4. `core/senf/exemplars.py` scores registered exemplars and
   `core/senf/identity.py` builds a graded, conflict-aware identity graph.
5. `core/senf/weave.py` aligns query frames with recalled source frames by the
   configured beam or hierarchical engine. The hierarchical polish is in
   `core/senf/weave_hierarchy.py` and its bounded Sinkhorn solver is in
   `core/senf/sinkhorn.py`.
6. SENF signals influence candidate ordering through
   `core/query_scoring.py`. Optional executable adapters are generated by
   `core/senf/bridge.py`.
7. With Stage 7 enabled, `core/senf/temporal.py` authorizes branch and interval
   transport and compiles a bounded, query-local ordinary MeTTa theory.
8. `core/service.py` validates and executes candidate-specific transient
   statements through `core/reasoner.py`; they are not persisted in the shared
   AtomSpace.
9. Accepted SENF metadata is stored alongside `nl` and `pln` in Qdrant by
   `storage/vector_store.py`, then revalidated from source atoms when recalled.

## Beam versus hierarchical TransWeave

Both engines use the same finite query/source frames, pair hypotheses, component
costs, temporal transport decisions, policy ceilings, and final `WeaveResult`.
They differ in how pair hypotheses are selected.

`beam` is the default. `core/senf/weave.py` runs `_weave_source` independently
for each source SENF, keeps bounded search states, sorts deterministic results,
and returns the best `k`. It is locally cost-driven and mature enough to be the
compatibility baseline. It cannot form one globally coupled assignment across
multiple source SENFs.

`hierarchical` builds a fair, globally capped set of `FrameAlignment` candidates
across query frames and sources. `core/senf/weave_hierarchy.py` performs bounded
Sinkhorn/IPF polish over connected components and the global candidate set,
then uses deterministic exact maximum-weight assignment and bounded alternative
seeds. The soft coupling is diagnostic/support for hard selection; it is not an
executable probabilistic proof.

Hierarchical failure is closed. Invalid bounds, source/frame/pair caps,
infeasible support, non-convergence, allocation limits, and internal hierarchy
errors return an unaligned result with `fallback_reason`; they do not silently
switch to beam or claim convergence. `SENF_WEAVE_FORGET_FINE_COSTS=true` removes
fine costs from the first transport prior, not from candidate construction or
the final policy checks. `SENF_WEAVE_COARSE_IDENTITY=true` changes identity-cost
granularity. Both controls are experimental and default false.

For an engine comparison, hold every other setting, suite, gold file, generation
tape, dependency revision, and query policy fixed. Compare candidate recall and
alignment correctness before comparing end-to-end answers; a changed proof rate
alone does not establish a better alignment engine.

## Feature-provider symbol boundary

The canonical parser owns all canonical symbols and PLN statements. A feature
provider owns neither.

- `FeatureProvider.provide` returns only `FeatureBatch` evidence about source
  text. `core/senf/features.py` intentionally has no canonical-symbol or PLN
  field.
- `core/senf/langextract_features.py` rejects reserved symbol/PLN fields,
  unsupported extraction classes, non-allowlisted features, and, by default,
  non-exact LangExtract alignment.
- `core/senf/feature_binding.py` binds only identical `(start, end, surface)`
  spans to exactly one parser-created mention. Ambiguous and absent spans are
  rejected.
- The allowlist can update mention type/definiteness, add non-conflicting
  modality/time/location hints, or record a registered exemplar cue.
  Coreference remains evidence and never directly rewrites entity IDs or elects
  canonical symbols.
- Applied features and coreference evidence are persisted as an audit trail.
  Recall reconstructs canonical SENF from stored NL/PLN, reapplies that trail,
  and requires equality with the stored typed payload.
- Provider exceptions fail open to empty evidence unless the exception carries
  `fail_closed`; malformed persisted evidence fails closed by excluding that
  SENF record.

This boundary is the promotion invariant: provider-enabled runs may improve
advisory evidence but must never introduce a symbol or executable statement not
authorized by canonical parsing and statement validation.

## Persistence v7 and v5/v6 migration

`core/senf/types.py` writes `SENF_PAYLOAD_VERSION = 7` through
`senf_to_payload`. `senf_from_payload` accepts strict v7 or first applies one of
two narrow, in-memory migrations:

- v5 to v7 adds span/guard-compatible fields, reconstructs typed contextual and
  exemplar fields, and initializes the v7 feature/coreference audit fields.
- v6 to v7 preserves the already guarded model and initializes empty
  `applied_mention_features` and `coreference_evidence`.

Absent versions, v3/v4, future versions, malformed v5/v6, and malformed v7
return no SENF. Unknown fields do not make an otherwise invalid payload valid.
Cross-reference, source-span, source-atom, kind assertion, context, exemplar,
temporal, and feature-audit invariants are checked before a typed SENF is
returned.

Migration does not mutate Qdrant and no repository script bulk-upgrades stored
points. A legacy record remains legacy until rewritten by a future explicit
tool or normal re-ingestion. `storage/vector_store.py` keeps `nl`, `pln`, and the
namespaced SENF payload together. On recall, the parser does not trust the blob
alone: it re-extracts from stored `nl` and accepted `pln`, reapplies the audit,
and compares the semantic structures. This makes migration conservative but
means stale or forged records disappear from SENF context without currently
emitting a response-level rejection reason.

## Operational modalities

The practical implementation treats modality as typed context plus transport
policy, not as a general modal logic:

- Speaker/reporting, textual modality, time, and location are captured on
  frames and `ContextGuard` by `core/senf/extractor.py`.
- Weave cost components in `core/senf/weave.py` penalize mismatches. Optional
  `SENF_WEAVE_REQUIRE_CONTEXT_MATCH=true` upgrades selected mismatches to a
  hard compatibility requirement.
- Branches are a bounded rooted tree. Facts can flow only from an ancestor into
  a descendant context; nonactual-to-actual and sibling inheritance are denied.
- Validity intervals use ISO-8601 bounds, interval relations, and exponential
  gap decay. Temporal persistence denies identity across disjoint intervals.
- `rigid`, `flexible`, `contingent`, and `temporal` persistence policies govern
  identity/transport; `ghost` and `unfulfilled` entities cannot authorize facts.
- Stage 7 compiles only authorized source atoms into candidate-local ordinary
  MeTTa, degrades truth values by branch probability and temporal decay, and
  enforces statement and branch-theory bounds.

Speaker, report, location, and generic modality labels do not currently compile
special modal inference rules. They are provenance, identity guards, and
alignment costs. Promotion claims must name the exact modality being evaluated.

## Bridge default safety

`SENF_EMIT_BRIDGE_ATOMS` defaults to `false`. With the default, SENF can rank or
rewrite candidate queries, but it does not inject executable alignment rules.
When enabled, `core/senf/bridge.py` may create candidate-local `senf_adapter_*`
implications with cost-degraded truth values.

Executable bridges are restricted to root fact frames with source atom
provenance, equal polarity, equal arity, authorized branch transport, supported
entity identity, and compatible unguarded context. Nested `FrameRef` arguments
are rejected. Adapters are passed as trusted transient statements, validated in
`core/service.py`, and run in isolated reasoner state by `core/reasoner.py`.
They are not ingested into the shared knowledge base.

These restrictions reduce risk but do not demonstrate semantic validity. Bridge
mode remains experimental until a frozen paired suite shows no increase in
safety false positives or invalid execution, every proof can identify its
adapter and source provenance, cost degradation is observed in proof truth
values, and transient state isolation passes repeated/cross-case tests.

## Diagnostics

The `ReasonResponse.senf` object is produced by
`CanonicalSENFPLNParser.senf_telemetry()` and propagated by `core/service.py`.
Important fields include:

- Structure and identity: `frame_count`, `mention_count`,
  `identity_edge_count`, `negative_identity_edge_count`, `merge_count`, and
  `exemplar_count`.
- Provider audit: `feature_provider`, `applied_feature_count`,
  `provider_coreference_count`, and `feature_rejections`.
- Planning: `candidate_count`, `candidate_score_breakdown`,
  `query_rewritten_atom_count`, `bridge_atom_count`, and
  `counterfactual_theory_statement_count`.
- Weave: top-level distortion/pair/cost plus bounded `weave_summaries` with
  mappings, component costs, transport decisions, Sinkhorn residuals/objective,
  entropy, soft mass, convergence, fallback, rejection, and truncation counts.
- Stage 7: `branch_count`, `candidate_temporal_plans`, `executed_temporal_plan`,
  and `stage7_rejection`.

The `matched_soft_mass`, `global_residual_ratio`, and `alignment_confidence`
entries under `candidate_score_breakdown[].senf_components` are weighted,
rounded integer score contributions, not raw alignment measurements. Raw soft
mass and Sinkhorn residual values are reported in `weave_summaries` (including
`matched_soft_mass`, `unmatched_soft_mass`, and the global-stage residual in
`polish`); alignment confidence is the matched share of total soft mass, and the
residual ratio is derived from the global residual and configured tolerance.

Response bounds are `SENF_DIAGNOSTICS_MAX_WEAVES`,
`SENF_DIAGNOSTICS_MAX_ITEMS`, and `SENF_DIAGNOSTICS_MAX_EVIDENCE`. Truncation
metadata must be checked before treating an emitted list as complete. No
metrics exporter or persistent aggregate dashboard is implemented; response
diagnostics and benchmark JSON are currently the observability surface.

## Reproducing evaluation

### Unit and component correctness

Run deterministic tests without external LLM/services:

```bash
pytest -q -m "not requires_llm and not requires_services"
```

For focused component checks:

```bash
pytest -q tests/test_senf_extractor.py tests/test_senf_persistence.py
pytest -q tests/test_senf_identity.py tests/test_senf_exemplars.py
pytest -q tests/test_senf_weave.py tests/test_senf_sinkhorn.py tests/test_senf_weave_hierarchy.py
pytest -q tests/test_senf_features.py tests/test_senf_temporal.py
pytest -q tests/test_canonical_senf_pln_parser.py tests/test_service_senf_transactions.py tests/test_reasoner_transient.py
```

These are correctness checks, not component benchmark outcomes.

benchmark.

### Component evaluator

`scripts/evaluate_senf_components.py` runs without external services against
the strict versioned gold file `data/benchmarks/senf_components_v1.json`. It
pins all material settings and measures exact spans, exhaustive identity
merge/evidence pairs, exemplars, hit@k plus wrong guards, typed
frame/entity/role/exemplar/time/location mappings, exact executable-adapter
signatures, residual convergence, and same-process repeat determinism. Reproduce
the tracked JSON and Markdown reports with:

```bash
python scripts/evaluate_senf_components.py \
  --gold data/benchmarks/senf_components_v1.json \
  --format json \
  --output docs/benchmarks/senf_components_v1.json

python scripts/evaluate_senf_components.py \
  --gold data/benchmarks/senf_components_v1.json \
  --format markdown \
  --output docs/benchmarks/senf_components_v1.md
```

The fixture is a small deterministic component set, not held-out natural
language or end-to-end answer evidence. Identity gold partitions every extracted
mention pair; emitted evidence outside its positive labels is a false positive.

### Beam/hierarchical microbenchmark

`scripts/benchmark_weave_engines.py` is a deterministic, service-free synthetic
driver for beam and hierarchical weave selection. It varies frame count,
compatible-pair density, and source count; reports stable result hashes, source
order determinism, pair/candidate counts, residuals, fallbacks, work/cell bounds,
and descriptive wall time; and emits a beam-to-hierarchical ablation summary.
It bounds the number and magnitude of sizes/sparsities, sources, repetitions,
warmups, and top-k. Deterministic hashes are checked both repeatedly in-process
and from fresh Python processes by the test suite.
Run it without treating timing as a regression threshold:

```bash
python scripts/benchmark_weave_engines.py \
  --sizes 2,4 \
  --sparsities 0.0,0.25,1.0 \
  --sources 2 \
  --repeats 3 \
  --warmups 1 \
  --top-k 3 \
  --json-output docs/benchmarks/senf_weave_engine_microbenchmark.json \
  --markdown-output docs/benchmarks/senf_weave_engine_microbenchmark.md
```

The report records the command, environment, settings, revision, dependency
versions, and synthetic dataset hash. The synthetic fixture has no reviewed
semantic gold and does not measure parser generation, identity resolution with
real language, proof correctness, answer quality, provider cost, or service
latency. Its output therefore cannot promote either engine by itself.

### Provider evaluation

No provider-specific evaluation driver exists yet, and no result for that mode
is asserted here. Reserve these paths so provider evidence is not conflated
with the parser-owned component suite:

- `scripts/benchmark_senf_feature_provider.py` for provider exact-span quality,
  rejection categories, replay behavior, latency, and cost.
- `data/benchmarks/senf_feature_provider_v1.json` for reviewed provider cases.
- `data/benchmarks/results/senf_feature_provider_<run-id>.json` for raw output.

Until that script and fixture exist, use focused provider tests for correctness
and generation-tape replay for controlled behavior. Do not present pytest

## Promotion gates

A mode is not promoted merely because its unit tests pass. The applicable gate
must be predeclared and evaluated against a frozen baseline.

| Gate | Required evidence |
| --- | --- |
| Correctness | Deterministic tests pass; malformed, over-limit, nonfinite, unknown-version, and non-convergent inputs fail open or closed exactly as documented. |
| Component quality | Reviewed labels for identity, pair alignment, transport authorization, and provider features; report precision/recall and rejection reasons by category. |
| Safety | No regression in expected-no-proof cases, invalid execution, ingestion rejection, cross-branch leakage, false identity merge, or transient-state leakage. |
| End-to-end utility | Paired frozen-generation answer grading; report per-case changes and confidence/uncertainty, not only aggregate proof count. |
| Compatibility | With no usable SENF evidence and all opt-ins off, canonical candidates/order and ordinary-world behavior remain stable. |
| Resource bounds | Adversarial and scaling runs stay within configured frame, pair, cell, seed, iteration, branch, statement, and timeout limits without unbounded allocation. |
| Observability | Raw report contains full settings, truncation indicators, fallback/rejection reasons, provenance, timing, and hashes needed to replay it. |
| Operations | Deployment exposes the approved settings explicitly, defaults remain safe, rollback is one setting change, and mixed persisted versions have been exercised. |
